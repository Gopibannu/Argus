## Threat Matrix

| Threat ID | Threat & Attack Vector | How Attacker Tries It | Mitigation Implemented | Test That Proves It | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **THR-01** | **User Enumeration via Auth Timing** | Attacker probes `/api/auth/login` with various emails; measures response time differences to discover valid accounts. | Constant-time password hashing comparison using a dummy bcrypt hash when email is not found; uniform error message (`Invalid email or password.`). | `tests/auth.test.js: Test 4 (no enumeration)` | **CLOSED** |
| **THR-02** | **Credential Stuffing & Brute Force** | Attacker scripts automated dictionary attacks against `/api/auth/login`. | Express-rate-limit strictly constrains `/api/auth/login` to 15 attempts per 15 minutes per IP (`authLimiter`). | `tests/auth.test.js: Test 3 & 4` | **CLOSED** |
| **THR-03** | **Session Hijacking via Cross-Site Scripting (XSS)** | Malicious JavaScript injected via third-party library or DOM injection reads `document.cookie`. | Session tokens are set with `HttpOnly; SameSite=Strict; Secure`. Browser forbids JavaScript access to cookie. | `tests/auth.test.js: Test 6 (HttpOnly SameSite=Strict)` | **CLOSED** |
| **THR-04** | **Cross-Site Request Forgery (CSRF)** | Attacker tricks user's browser into sending authenticated state-changing requests from a malicious site. | Dual-layer: `SameSite=Strict` cookie prevents cross-site submission; HMAC-derived `X-CSRF-Token` verified on all state-modifying requests. | `tests/auth.test.js: Test 7 (CSRF token verification on logout)` | **CLOSED** |
| **THR-05** | **Stateless JWT Stale Access / Revocation Delay** | User account deactivated or permissions revoked; attacker uses valid unexpired JWT to keep querying data for 15 minutes. | **No stateless JWTs.** Server-side opaque sessions stored in PostgreSQL. Every request checks live DB status (`is_active = true`). | `tests/auth.test.js: Test 5 & 7 (instant invalidation)` | **CLOSED** |
| **THR-06** | **Session Replay After Logout** | Attacker captures raw session cookie and replays it after the victim clicks "Log Out". | Session row is deleted from database upon logout; subsequent requests return 401. | `tests/auth.test.js: Test 7` | **CLOSED** |
| **THR-07** | **Concurrent Device Session Persistence** | Attacker compromises one device session; victim clicks "Log Out Everywhere" from another device. | `/api/auth/logout-all` deletes all session rows for that `user_id` across all devices in a single query. | `tests/auth.test.js: Test 8` | **CLOSED** |
| **THR-08** | **Clickjacking UI Redress** | Attacker frames Argus application inside an iframe to hijack user clicks. | Helmet sets `frame-ancestors: 'none'` in Content-Security-Policy and `X-Frame-Options: DENY`. | `tests/auth.test.js: Test 1 (security headers)` | **CLOSED** |
| **THR-09** | **MIME Sniffing & XSS Confusion** | Attacker uploads malicious script disguised as harmless media. | Helmet sets `X-Content-Type-Options: nosniff` and file downloads enforce binary streams. | `tests/documents.test.js: Test 1 & 4` | **CLOSED** |
| **THR-10** | **Database Audit Log Tampering** | Attacker or malicious DBA attempts `UPDATE` or `DELETE` on `audit_log` to remove evidence. | PostgreSQL trigger `prevent_audit_tampering()` raises exception on UPDATE, DELETE, and TRUNCATE; SHA-256 hash chain detects alteration. *Residual risk: DB superuser with ALTER TABLE can disable triggers; mitigated in prod via restricted app role.* | `tests/audit.test.js: Test 5, 6, 7` | **PARTIALLY MITIGATED** |
| **THR-11** | **IDOR & Existence Enumeration** | Attacker guesses document UUIDs (`/api/documents/:id`); probing 403 vs 404 to discover existence of confidential documents. | Server returns uniform **404 Not Found** for both non-existent AND unauthorized documents. Still logs denied attempt. | `tests/documents.test.js: Test 5, 6, 7 & tests/authzMatrix.test.js: Matrix 2, 4` | **CLOSED** |
| **THR-12** | **Direct Storage URL Access & Predictable Keys** | Attacker accesses cloud storage bucket directly to bypass server authorization. | Bucket is 100% private with public access disabled. Files streamed strictly via `authorize()` using server service role; storage keys are random UUIDs. | `tests/documents.test.js: Test 4` | **CLOSED** |
| **THR-13** | **Unrestricted File Upload & Magic-Byte Spoofing** | Attacker uploads `.php`, `.exe`, or polyglot files with fake extensions to execute arbitrary code. | Strict magic-byte inspection (not client extension/MIME), random UUID storage keys, and 10MB size limits. Macro-enabled office docs rejected. | `tests/documents.test.js: Test 1, 2` | **CLOSED** |
| **THR-14** | **Privilege Escalation via Grantee Re-Sharing** | Grantee with `read` or `edit` rights attempts to grant access to unauthorized third parties or delete document. | Single choke point `authorize()` reserves `grant`, `revoke`, and `delete` strictly for document owners. Grantees cannot re-share. | `tests/documents.test.js: Test 11, 12 & tests/authzMatrix.test.js: Matrix 5, 6` | **CLOSED** |
| **THR-15** | **Stale Download Ticket Replay After Revocation** | Grantee holds pre-issued 60s ticket; owner revokes grant; grantee uses ticket before expiry. | Document increments `grant_version` on every grant/revoke; ticket redemption checks `ticket.grant_version_at_issue === doc.live_grant_version`. Single-use enforcement rejects replay attempts with 403. | `tests/documents.test.js: Test 13 & Test 14` | **CLOSED** |
| **THR-16** | **AI Prompt Injection via Document Title** | Malicious document title contains prompt injection designed to force AI suggestion to widen access. | AI suggestions receive sanitized metadata only; output is strictly validated against existing active user UUIDs; suggestions never auto-grant (human-in-the-loop); both suggestion and decision logged to audit chain. | `tests/ai.test.js: Test 1, 2, 3, 4` | **CLOSED** |
| **THR-17** | **Free Tier Cold Starts & Provider Admin Risk** | Free tier spin-down delays requests (30-50s); host provider root admin can view disks. | Cold starts accepted as platform constraint. Immutability enforced via `BEFORE UPDATE`, `BEFORE DELETE`, and `BEFORE TRUNCATE` triggers plus restricted least-privilege `argus_app_user` database role. | Documented in `docs/WRITEUP.md` | **ACCEPTED RISK** |
| **THR-18** | **Registration Mass Assignment & Role Escalation** | Attacker sends `role: 'admin'` or `role: 'owner'` in registration payload to self-provision privileges. | Request field whitelisting excludes `role`. Public registration strictly hardcoded to `role: 'viewer'`. Elevated roles require existing admin provisioning. | `tests/auth.test.js: Test 9` | **CLOSED** |
| **THR-19** | **OTP Endpoint Abuse & SMS/Email Bombing** | Attacker floods `/api/auth/initiate-register` to exhaust email quotas and spam victims. | Strict rate limiter (`otpLimiter`) caps OTP dispatches to 5 requests per 15 minutes per IP. 10-minute expiry enforced. | `tests/auth.test.js: Test 11 & 12` | **CLOSED** |
| **THR-20** | **Audit Hash Chain Forking via Concurrent Writes** | Simultaneous requests read identical `prev_hash` concurrently and generate forked chain branches. | PostgreSQL session advisory locking (`SELECT pg_advisory_lock(1095911253)`) serializes audit row insertions atomically. | `tests/audit.test.js: Test 1, 2` | **CLOSED** |
| **THR-21** | **Search Query Metadata & Existence Leaks** | Attacker searches document catalog using wildcard queries to enumerate ungranted titles. | SQL search join strictly joins `grants` table and owner ID; ungranted files are never returned or counted in search results. | `tests/authzMatrix.test.js: Matrix 9` | **CLOSED** |
| **THR-22** | **Reverse Proxy IP Spoofing (`X-Forwarded-For`)** | Attacker spoofs `X-Forwarded-For` header to evade rate limits or poison audit IP records. | Express configured with `app.set('trust proxy', 1)` to trust only the immediate upstream Render/reverse-proxy edge hop. | `server/src/middleware/security.js` | **CLOSED** |
